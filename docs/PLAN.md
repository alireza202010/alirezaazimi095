# پلن محصول: دستیار هوشمند لینک‌سازی و رپورتاژ برای وب فارسی

> کاربر بودجه و اطلاعات سایتش را وارد می‌کند؛ سیستم بر اساس آن یک «پلن لینک‌سازی» قابل اجرا در وب فارسی پیشنهاد می‌دهد (رپورتاژ، بک‌لینک، خبرگزاری، دایرکتوری، شبکه‌های اجتماعی و ...) با زمان‌بندی، انکرتکست، صفحه هدف و هزینه‌ی دقیق.

---

## ۱. تعریف محصول

### مسئله
- صاحبان سایت نمی‌دانند با بودجه‌ی مشخص کدام رپورتاژ / بک‌لینک را بخرند.
- DA و DR بسیاری از سایت‌های فارسی دستکاری شده و قیمت‌ها با کیفیت واقعی هم‌خوانی ندارد.
- انتخاب انکرتکست، صفحه هدف و سرعت لینک‌سازی (Link Velocity) معمولاً حدسی است و ریسک پنالتی دارد.
- بازارگاه‌های فعلی رپورتاژ فقط «فهرست قیمت» می‌دهند، نه «استراتژی».

### ارزش پیشنهادی (تمایز)
**«مدیا پلنر لینک‌سازی»** — نه یک فروشگاه رپورتاژ دیگر:
1. ورودی: بودجه + هدف → خروجی: پلن بهینه و قابل اجرا.
2. امتیاز کیفیت مستقل برای هر ناشر (بر اساس ترافیک واقعی، ارتباط موضوعی، نشانه‌های اسپم)، نه فقط DA.
3. تحلیل شکاف لینک با رقبا (سایت‌هایی که به رقیب لینک داده‌اند ولی به شما نه).
4. مدیریت ریسک: توزیع انکرتکست، تنوع منابع، سرعت طبیعی لینک‌سازی.
5. پایش بعد از خرید: لینک هنوز زنده است؟ ایندکس شده؟ فالو مانده؟ رتبه‌ها چه تغییری کرده؟

### پرسونا‌ها
| پرسونا | نیاز اصلی |
|---|---|
| صاحب کسب‌وکار / فروشگاه اینترنتی کوچک | «با ۱۰ میلیون تومان در ماه بهترین کار چیست؟» |
| کارشناس سئو فریلنسر | صرفه‌جویی در زمان تحقیق و گزارش‌دهی به کارفرما |
| آژانس دیجیتال مارکتینگ | مدیریت چند پروژه، وایت‌لیبل، API |

## ۲. ورودی‌های کاربر (فرم Onboarding)

**اجباری:**
- آدرس سایت
- بودجه (کل یا ماهانه) و مدت کمپین (۱، ۳، ۶، ۱۲ ماه)
- حوزه فعالیت (دسته‌بندی از لیست + توضیح آزاد)
- ۳ تا ۲۰ کلمه کلیدی هدف + صفحه هدف هر کدام

**اختیاری (دقت پلن را بالا می‌برد):**
- ۲ تا ۵ رقیب اصلی
- هدف اصلی: رتبه کلمات کلیدی / برندینگ / ترافیک ارجاعی / سئو محلی
- سطح ریسک‌پذیری: محافظه‌کار / متعادل / تهاجمی
- ترجیحات: فقط خبرگزاری، فقط سایت‌های تخصصی، نیاز به دائمی بودن لینک، رپورتاژ با نویسندگی ما یا خودشان
- اتصال Google Search Console (OAuth) برای دیتای واقعی
- منطقه جغرافیایی (برای سئو محلی)

## ۳. داده‌ها — قلب محصول

### ۳.۱ دیتابیس ناشران (Publisher Inventory)
برای هر سایت ناشر:
- **مشخصات:** دامنه، دسته‌بندی موضوعی، نوع (خبرگزاری رسمی / سایت خبری / مجله تخصصی / وبلاگ / دایرکتوری / فروم)
- **محصولات و قیمت‌ها:** رپورتاژ معمولی، رپورتاژ خبری، بک‌لینک سایدبار/فوتر، پست مهمان؛ با ویژگی‌هایی مثل تعداد لینک مجاز، فالو/نوفالو/sponsored، دائمی یا موقت، مدت نمایش در صفحه اول، انتشار در شبکه‌های اجتماعی، زمان انتشار
- **متریک‌ها (سری زمانی):**
  - اعتبار: DA/DR/Authority (از APIهای خارجی یا OpenPageRank)
  - ترافیک ارگانیک تخمینی و تعداد کلمات رتبه‌دار در گوگل
  - تعداد صفحات ایندکس شده
  - **نسبت لینک خروجی** (تعداد رپورتاژ منتشرشده در ماه ← تشخیص لینک‌فارم)
  - سن دامنه، سرعت سایت، HTTPS
  - نرخ ایندکس شدن رپورتاژهای قبلی

### ۳.۲ منابع جمع‌آوری
| منبع | روش |
|---|---|
| تعرفه‌ی رپورتاژ سایت‌ها و بازارگاه‌های موجود | خزش (Scrapy/Playwright) + ورود دستی + پنل ثبت‌نام ناشر |
| متریک‌های اعتبار و ترافیک | DataForSEO / Ahrefs / Semrush / Moz API (توجه: پرداخت ارزی و تحریم) یا OpenPageRank رایگان + تخمین داخلی |
| ترافیک و رتبه واقعی | خزنده‌ی SERP اختصاصی برای کلمات فارسی |
| دیتای خود کاربر | Google Search Console API |
| بک‌لینک‌های رقبا | API بک‌لینک (DataForSEO Backlinks / Ahrefs) |

> نکته: در شروع، **۳۰۰ تا ۵۰۰ ناشر با کیفیت را دستی و دقیق** وارد کنید. کیفیت داده از تعداد مهم‌تر است.

## ۴. موتور پیشنهاد (Recommendation Engine)

### گام ۱ — تحلیل سایت کاربر
- پروفایل لینک فعلی، توزیع انکرتکست، دامنه‌های ارجاع‌دهنده
- سختی کلمات کلیدی و فاصله با رقبا
- تعیین «تعداد لینک موردنیاز» تقریبی برای هر کلمه

### گام ۲ — امتیازدهی ناشران
```
Quality = w1·Authority_norm + w2·Traffic_norm + w3·Relevance
        + w4·IndexRate − w5·SpamRisk − w6·OutboundLinkRatio

Value_per_Toman = Quality / Price
```
- **Relevance:** شباهت موضوعی محتوای ناشر با حوزه کاربر (Embedding متن فارسی + دسته‌بندی)
- **SpamRisk:** ترافیک پایین با DA بالا، حجم زیاد رپورتاژ، افت ناگهانی ترافیک
- وزن‌ها بسته به هدف و سطح ریسک کاربر تغییر می‌کنند

### گام ۳ — بهینه‌سازی سبد (مسئله کوله‌پشتی با قید)
با برنامه‌ریزی عدد صحیح (OR-Tools یا PuLP):
- **هدف:** بیشینه‌کردن مجموع Value
- **قیدها:**
  - مجموع هزینه ≤ بودجه
  - حداکثر یک خرید از هر دامنه (یا طبق سیاست)
  - ترکیب نوع منبع (مثلاً ٪۲۰–۴۰ خبرگزاری، ٪۴۰+ تخصصی هم‌موضوع)
  - حداقل Relevance
  - توزیع زمانی یکنواخت در ماه‌ها (Link Velocity طبیعی)
  - توزیع صفحات هدف بین کلمات کلیدی

### گام ۴ — تولید خروجی
- لیست اقلام: ناشر، نوع محصول، قیمت، ماه انتشار، صفحه هدف، **انکرتکست پیشنهادی**
- توزیع انکرتکست (پیش‌فرض: برند ~٪۴۰، URL خالی ~٪۲۰، عمومی ~٪۱۵، Partial ~٪۱۵، Exact ≤ ٪۱۰)
- پیشنهاد موضوع و بریف محتوای رپورتاژ (با LLM)
- پیش‌بینی اثر به‌صورت بازه و با زبان صادقانه (نه وعده رتبه)
- ۲–۳ سناریوی جایگزین (اقتصادی / متعادل / پرقدرت)
- خروجی PDF / اکسل قابل ارائه به کارفرما

> نسخه اول را **قانون‌محور (Rule-based)** بسازید؛ مدل یادگیری ماشین فقط وقتی معنی دارد که داده‌ی «لینک ← تغییر رتبه» کافی جمع شده باشد.

## ۵. فیچرها به تفکیک نسخه

| نسخه | فیچرها |
|---|---|
| **MVP** | فرم ورودی، دیتابیس ناشران، امتیازدهی، پلن بهینه، خروجی PDF، ثبت‌نام با موبایل |
| **V1** | ثبت سفارش و پرداخت در پلتفرم، پنل ناشران، تولید محتوای رپورتاژ (AI + ویراستار انسانی)، پایش لینک‌ها |
| **V2** | تحلیل شکاف رقبا، رنک ترکر فارسی، اتصال GSC و گزارش قبل/بعد، داشبورد آژانس و وایت‌لیبل |
| **V3** | API، مدل پیش‌بینی اثر بر اساس داده‌های واقعی، پیشنهاد خودکار ماه‌به‌ماه |

## ۶. معماری فنی پیشنهادی

- **Backend:** Python + FastAPI (یا Django) — مناسب برای خزش، تحلیل داده و بهینه‌سازی
- **Database:** PostgreSQL (+ pgvector برای Embedding)
- **صف و کارهای زمان‌بندی‌شده:** Redis + Celery (به‌روزرسانی متریک‌ها، پایش لینک‌ها)
- **خزنده:** Scrapy + Playwright
- **بهینه‌سازی:** Google OR-Tools
- **Frontend:** Next.js + Tailwind، راست‌چین، فونت وزیرمتن، تاریخ شمسی
- **گزارش:** WeasyPrint یا Puppeteer برای PDF فارسی
- **زیرساخت:** هاست داخل ایران برای اپ اصلی (درگاه پرداخت، اینماد) + سرور خارج برای خزش و APIهای خارجی
- **پرداخت:** زرین‌پال / آیدی‌پی / درگاه بانکی + کیف پول داخلی

### مدل داده (جدول‌های اصلی)
```
users, projects, project_inputs, keywords, competitors
publishers, publisher_metrics (time-series), publisher_offers
plans, plan_items, orders, placed_links, link_checks, rank_snapshots
```

## ۸. مدل درآمدی

1. **پلن رایگان محدود** (مثلاً ۵ پیشنهاد اول) به‌عنوان قلاب جذب ← پلن کامل پولی یا با ثبت سفارش رایگان
2. **کمیسیون سفارش** (٪۱۰–۲۰ روی قیمت رپورتاژ) — درآمد اصلی
3. **اشتراک ماهانه** برای پایش لینک، رنک ترکر، گزارش دوره‌ای
4. **پلن آژانسی** با چند پروژه و وایت‌لیبل
5. **خدمات جانبی:** نگارش رپورتاژ، مشاوره

## ۹. ریسک‌ها و راهکارها

| ریسک | راهکار |
|---|---|
| **سیاست‌های گوگل:** خرید لینک برای رتبه طبق Spam Policies گوگل تخلف است و الگوریتم‌هایی مثل SpamBrain لینک‌های غیرطبیعی را بی‌اثر یا جریمه می‌کنند | شفافیت با کاربر، امتیاز ریسک، تنوع منابع، تأکید بر ارتباط موضوعی و ترافیک واقعی، پیشنهاد گزینه‌های امن‌تر (محتوای ارزشمند، PR دیجیتال، brand mention) |
| متریک‌های دستکاری‌شده (DA فیک) | تکیه بر ترافیک واقعی، نسبت لینک خروجی و نرخ ایندکس |
| تغییر مداوم قیمت ناشران | خزش دوره‌ای + پنل اختصاصی ناشر + تاریخ آخرین به‌روزرسانی روی هر قیمت |
| هزینه و محدودیت پرداخت APIهای خارجی | شروع با منابع ارزان/رایگان، کش‌کردن، ساخت متریک داخلی |
| اعتماد کاربر | نمایش منطق هر پیشنهاد («چرا این سایت؟»)، نمونه پلن، گزارش قبل/بعد |
| حذف یا نوفالو شدن لینک پس از خرید | پایش خودکار، ضمانت و بازپرداخت از طرف ناشر در قرارداد |
| حقوقی | اینماد، قرارداد با ناشران، شرایط استفاده و سلب مسئولیت درباره نتایج |

## ۱۰. شاخص‌های موفقیت (KPI)

- نرخ تکمیل فرم ورودی و تبدیل «پلن ← سفارش»
- میانگین ارزش سفارش و درآمد کمیسیون ماهانه
- درصد لینک‌های زنده و ایندکس‌شده پس از ۳۰ و ۹۰ روز
- بهبود رتبه کلمات کلیدی کاربران (میانه، پس از ۹۰ روز)
- نرخ بازگشت کاربر برای پلن ماه بعد

## ۱۱. قدم‌های همین هفته

1. ۱۰ نفر از مشتریان هدف را پیدا و مصاحبه کنید: «الان چطور رپورتاژ انتخاب می‌کنید؟ چقدر خرج می‌کنید؟»
2. یک شیت با ۱۰۰ ناشر اول (دامنه، دسته، قیمت، نوع لینک، ترافیک) بسازید.
3. فرمول امتیازدهی را در همان شیت پیاده کنید و برای ۳ سایت واقعی دستی پلن بسازید.
4. اگر کاربران حاضر به پرداخت بودند ← شروع فاز ۱.
