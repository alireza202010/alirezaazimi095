# ایجنت لیدیابی هاشین گلد — طلافروشی‌های تهران

**هدف:** هاشین گلد تولیدکننده عمده **شمش طلای ۷۵۰ عیار** است و دنبال طلافروشی‌هایی در تهران می‌گردد که
**نماینده فروش** شمش‌هایش شوند. این ایجنت طلافروشی‌ها، گالری‌ها، جواهری‌ها و فروشندگان آبشده/شمش/سکه تهران را پیدا
می‌کند، هر کدام را در یکی از **۲۲ منطقه شهرداری** قرار می‌دهد، شماره تماس و اطلاعاتشان را جمع می‌کند، می‌سنجد
**چقدر برای نمایندگی مناسب‌اند**، و برای هر منطقه بهترین کاندیدها را در یک **گوگل‌شیت** به تیم فروش معرفی می‌کند
(یک نسخه اکسل و CSV هم در پوشه `output/` ساخته می‌شود).

## ایجنت چه کار می‌کند؟

```
 جمع‌آوری           ادغام تکراری‌ها     تعیین منطقه          تحقیق با AI           امتیازدهی       گوگل‌شیت
 Google Maps  ─┐
 نشان          ├──►  یک ردیف برای   ──►  منطقه ۱ تا ۲۲   ──►  Claude در وب      ──►  رتبه A/B/C ──►  تب برای هر منطقه
 OpenStreetMap ─┘     هر مغازه                              می‌گردد (اختیاری)
```

1. **جمع‌آوری** (`leadgen/sources/`)
   - عبارت‌های جستجو علاوه بر «طلا فروشی / گالری طلا / جواهری» شامل **«طلای آبشده»، «شمش و سکه طلا»، «سکه و طلا»**
     هم هست تا مغازه‌هایی که الان طلای سرمایه‌ای می‌فروشند (بهترین کاندیدهای نمایندگی) حتماً پیدا شوند.
   - **Google Places API**: کامل‌ترین منبع؛ تلفن، وبسایت، امتیاز و تعداد نظرات. تهران به چند خانه تقسیم می‌شود و
     هر خانه‌ای که پر برگردد (گوگل حداکثر ۶۰ نتیجه می‌دهد) دوباره به ۴ خانه کوچک‌تر تقسیم می‌شود تا چیزی جا نماند.
   - **نشان (Neshan Search API v3)**: پوشش خیلی خوب مغازه‌های ایرانی؛ روی یک شبکه نقاط (پیش‌فرض هر ۲ کیلومتر) جستجو می‌کند.
     اگر کلید اجازه جستجو نداشته باشد، با یک پیام روشن رد می‌شود و بقیه منابع ادامه می‌دهند (تعیین منطقه با همان کلید کار می‌کند).
   - **Map.ir (مپ)**: نقشه ایرانی دوم با API جستجو؛ جایگزین وقتی جستجوی نشان در دسترس نیست.
   - **OpenStreetMap (Overpass)**: رایگان و بدون کلید؛ پوشش کمتر ولی گاهی تلفن و اینستاگرام دارد.
2. **ادغام** (`dedupe.py`): یک مغازه که در چند منبع یا چند جستجو آمده یکی می‌شود (نام مشابه + فاصله کمتر از ۸۰ متر،
   یا تلفن مشترک، یا شناسه یکسان). مغازه‌های کناری در بازار با نام متفاوت، و شعبه‌های دور یک برند، جدا می‌مانند.
3. **تعیین منطقه** (`districts.py`) به ترتیب دقت — ستون «دقت منطقه» نشان می‌دهد کدام روش استفاده شده:
   1. پاسخ `municipality_zone` از Reverse Geocoding نشان (دقیق)
   2. مرز مناطق (دانلود از OpenStreetMap با `python -m leadgen districts` یا فایل GeoJSON خودتان)
   3. «منطقه ۶» در متن آدرس
   4. نام محله‌های شناخته‌شده از `data/neighbourhoods.json` (تقریبی؛ قابل ویرایش)
4. **تحقیق با هوش مصنوعی** (`enrich.py`، اختیاری با `--enrich`): برای هر لید یک ایجنت Claude در وب
   (اینستاگرام، سایت، نقشه‌ها، دایرکتوری‌ها) می‌گردد و برمی‌گرداند:
   - تلفن ثابت و موبایل، اینستاگرام و **تعداد فالوور**، وبسایت
   - **آیا شمش / آبشده / سکه می‌فروشد؟** و **برندهای شمش/سکه‌ای که الان می‌فروشد یا نماینده‌شان است**
     (تجربه دارد، ولی ممکن است قرارداد انحصاری داشته باشد — در «دلیل تناسب» ذکر می‌شود)
   - آیا **عمده‌فروشی / پخش به همکار** دارد، نوع کسب‌وکار، اندازه، تعداد شعب
   - **تناسب برای نمایندگی** (بالا / متوسط / پایین) با دلیل، یک یادداشت برای فروشنده، و یک
     **پیام پیشنهادی اول** کوتاه برای دایرکت اینستاگرام یا واتساپ

   اول مغازه‌هایی بررسی می‌شوند که نامشان نشان می‌دهد آبشده/شمش/سکه می‌فروشند، بعد پرمراجعه‌ترها. ایجنت مجاز نیست
   شماره حدس بزند یا شرایط تجاری (قیمت، پورسانت، تخفیف) از خودش بسازد؛ هر شماره دوباره اعتبارسنجی می‌شود.
   نتیجه‌ها کش می‌شوند تا در اجرای بعد دوباره هزینه نشود.
5. **امتیاز لید** (`scoring.py`): دو بخش دارد — **تناسب** (فروش شمش/آبشده/سکه، پخش عمده، نظر AI، اندازه، شعب،
   فالوور، نظرات گوگل) و **قابل‌دسترس بودن** (تلفن، موبایل، اینستاگرام) → امتیاز ۰ تا ۱۰۰ و رتبه A / B / C
   (بسته‌شده: D). یک جواهری بزرگ که سرمایه‌ای نمی‌فروشد پایین‌تر از یک فروشنده آبشده فعال قرار می‌گیرد.
   وزن‌ها را با تجربه تیم (چه مغازه‌هایی واقعاً نماینده شدند) تنظیم کنید.

## خروجی در گوگل‌شیت

| تب | محتوا |
|---|---|
| **خلاصه مناطق** | برای هر منطقه: تعداد لید، دارای تلفن/موبایل/اینستاگرام، فروشنده شمش/آبشده/سکه، تناسب بالا، A/B/C، پیگیری‌شده و قرارداد نمایندگی |
| **کاندیدهای نمایندگی** | **۳ کاندید برتر هر منطقه** که هنوز رد نکرده‌اند و قرارداد نبسته‌اند — اگر یکی رد کند، نفر بعدی جایش می‌آید |
| **همه لیدها** | همه مغازه‌ها، مرتب بر اساس منطقه و امتیاز (با «رتبه در منطقه») |
| **منطقه ۱ … منطقه ۲۲، نامشخص** | لیدهای هر منطقه (برای تقسیم بین فروشنده‌ها) |

ستون‌ها: منطقه، محله، نام فروشگاه، تلفن ثابت، موبایل، اینستاگرام، وبسایت، آدرس، رتبه و امتیاز لید، رتبه در منطقه،
**تناسب برای نمایندگی** و دلیلش، **فروش شمش/آبشده/سکه**، **برندهای شمش/سکه فعلی**، عمده‌فروش/پخش، نوع کسب‌وکار،
اندازه، تعداد شعب، فالوور اینستاگرام، امتیاز و تعداد نظرات گوگل، یادداشت AI، **پیام پیشنهادی اول**، لینک گوگل‌مپ و نشان،
ساعات کاری، **وضعیت** (لیست کشویی: جدید / پیام ارسال شد / تماس گرفته شد / پاسخ نداد / علاقه‌مند به نمایندگی /
ارسال شرایط نمایندگی / جلسه حضوری / قرارداد نمایندگی / رد کرد / شماره اشتباه)، **مسئول فروش**، **تاریخ آخرین تماس**،
**یادداشت فروش**، منابع داده، دقت منطقه، مختصات، اولین مشاهده، آخرین بروزرسانی.

**تیم فروش با خیال راحت کار کند:** هر بار که ایجنت دوباره اجرا می‌شود، چهار ستون فروش (وضعیت، مسئول، تاریخ تماس،
یادداشت) دست نمی‌خورند — چه در تب «همه لیدها» ویرایش شده باشند، چه در تب منطقه یا «کاندیدهای نمایندگی». ردیف‌هایی که دستی اضافه شده‌اند
یا این بار پیدا نشده‌اند هم حذف نمی‌شوند. (یک تب مخفی `_sync` برای تشخیص ویرایش‌ها استفاده می‌شود؛ پاکش نکنید.)

## راه‌اندازی

```bash
cd gold_leads
pip install -r requirements.txt
```

کلیدها را در فایل `gold_leads/.env` بنویسید (از روی `.env.example` کپی کنید؛ این فایل در git ثبت نمی‌شود)
یا به‌صورت متغیر محیطی بدهید. هر منبعی که کلیدش نباشد رد می‌شود. بعد با این دستور همه را تست کنید:

```bash
python -m leadgen check
```

خروجی برای هر سرویس `OK` / `FAIL` / `--` (تنظیم نشده) نشان می‌دهد؛ برای هر کدام فقط یک درخواست ارزان می‌فرستد.

| متغیر | از کجا | برای |
|---|---|---|
| `NESHAN_API_KEY` | [platform.neshan.org](https://platform.neshan.org) → کلیدهای دسترسی → تب «سرویس‌ها» → سرویس «تبدیل نقطه به آدرس» (و «جستجو» اگر در فهرست بود). کلید با `service.` شروع می‌شود. در سرور MCP رسمی نشان، جستجو و تبدیل نقطه به آدرس یک گروه کلید مشترک دارند؛ `check` نشان می‌دهد جستجو برای کلید شما باز است یا نه | تعیین دقیق منطقه + منبع نشان |
| `MAPIR_API_KEY` | [corp.map.ir](https://corp.map.ir) → ثبت‌نام و دریافت کلید (سرویس جستجو) | منبع Map.ir |
| `GOOGLE_MAPS_API_KEY` | Google Cloud Console → فعال‌سازی **Places API (New)** | منبع گوگل (تلفن، امتیاز، نظرات) |
| `ANTHROPIC_API_KEY` | [console.anthropic.com](https://console.anthropic.com) | تحقیق AI (`--enrich`) |
| `GOOGLE_SERVICE_ACCOUNT_FILE` | Google Cloud → Service Account → کلید JSON؛ سپس شیت را با ایمیل این سرویس‌اکانت **Share (Editor)** کنید. Sheets API هم باید فعال باشد | نوشتن در گوگل‌شیت |
| `GOOGLE_SHEET_ID` | بخش بین `/d/` و `/edit` در لینک شیت | شیت مقصد |
| `BUSINESS_CONTEXT` | (اختیاری) توضیح پیشنهاد نمایندگی. پیش‌فرض: «هاشین گلد تولیدکننده عمده شمش طلای ۷۵۰ است و نماینده فروش جذب می‌کند». مزیت‌های واقعی‌تان (وزن‌های موجود، بسته‌بندی/فاکتور، حاشیه سود، تسویه، ...) را اینجا بنویسید؛ به متن پیش‌فرض اضافه می‌شود تا یادداشت‌ها و پیام‌های AI دقیق‌تر شوند؛ AI چیزی بیش از این متن ادعا نمی‌کند | پیام‌ها و یادداشت‌های فروش |

## اجرا

```bash
# (یک بار) دانلود مرز ۲۲ منطقه از OpenStreetMap — وقتی کلید نشان ندارید مفید است
python -m leadgen districts

# تست کلیدها
python -m leadgen check

# اجرای کامل: جمع‌آوری از همه منابعی که کلید دارند + نوشتن در شیت
python -m leadgen run

# با تحقیق AI برای ۱۰۰ لید (اول فروشندگان آبشده/شمش/سکه)
python -m leadgen run --enrich --enrich-limit 100

# فقط منبع رایگان OSM، بدون شیت (فقط اکسل در output/)
python -m leadgen run --sources osm
```

گزینه‌های مهم: `--sources google,neshan,mapir,osm` · `--grid-step 0.02` (فاصله نقاط جستجوی نشان؛ کوچک‌تر = کامل‌تر ولی درخواست بیشتر) ·
`--model` و `--effort` و `--workers` برای تحقیق AI · `--districts-file my_districts.geojson` · `--out` · `-v`.

پیشنهاد: هفته‌ای یک بار با cron اجرا شود تا مغازه‌های جدید اضافه شوند؛ کش‌ها در `cache/` نگه داشته می‌شوند تا درخواست‌های
تکراری (Reverse Geocoding و تحقیق AI) دوباره هزینه نشوند.

## هزینه و محدودیت‌ها (تقریبی)

- **گوگل:** هر درخواست Text Search با فیلد تلفن در رده Enterprise قیمت‌گذاری می‌شود؛ پوشش کامل تهران با چهار عبارت
  جستجو معمولاً چند صد تا حدود هزار درخواست است. سهمیه رایگان ماهانه گوگل را در کنسول چک کنید. استفاده از Google Maps Platform
  برای ایران ممکن است با محدودیت‌های تحریمی/حساب کاربری مواجه شود؛ اگر کار نکرد، نشان + OSM + تحقیق AI کافی است.
- **Map.ir:** مثل نشان روی شبکه نقاط (۴ عبارت) جستجو می‌کند؛ سهمیه پلن را چک کنید.
- **نشان:** با `--grid-step 0.02` حدود ۳۵۰ نقطه × ۵ عبارت ≈ ۱۷۵۰ درخواست جستجو + یک Reverse برای هر مغازه. سهمیه
  پلن نشان را چک کنید. نشان شماره تلفن نمی‌دهد؛ تلفن از گوگل/OSM یا تحقیق AI می‌آید.
- **Claude:** هزینه به تعداد جستجوهای وب و طول صفحات بستگی دارد؛ ابتدا با `--enrich-limit 10` یک تست بگیرید و هزینه را در
  کنسول ببینید، بعد بیشتر کنید. مدل پیش‌فرض `claude-opus-5-5` است (با `--model` قابل تغییر) و اگر درخواستی توسط
  فیلتر ایمنی رد شود، به‌صورت خودکار روی مدل جایگزین اجرا می‌شود (`fallbacks: "default"`).
- **داده عمومی کسب‌وکار:** فقط اطلاعاتی جمع می‌شود که خود مغازه‌ها عمومی منتشر کرده‌اند. قبل از تماس انبوه یا ارسال
  پیامک تبلیغاتی، قوانین مربوط (از جمله ثبت و رضایت برای پیامک تبلیغاتی) را رعایت کنید.

## تست

```bash
pytest -q
```

تست‌ها هیچ درخواست واقعی نمی‌زنند (HTTP، Claude و گوگل‌شیت شبیه‌سازی شده‌اند).

## ساختار کد

```
leadgen/
  agent.py          ارکستراتور (collect → dedupe → districts → enrich → score → sheet)
  sources/          google_places.py · neshan.py · mapir.py · osm.py
  districts.py      تعیین منطقه شهرداری
  dedupe.py         ادغام تکراری‌ها
  enrich.py         ایجنت تحقیق Claude (web search + ابزار submit_lead_info)
  scoring.py        امتیاز و رتبه لید
  table.py          ساخت تب‌ها و حفظ ستون‌های فروش
  sheets.py         همگام‌سازی گوگل‌شیت (چند فراخوانی batch)
  export.py         اکسل و CSV
data/neighbourhoods.json   نگاشت محله → منطقه (fallback)
```
