# لینک‌پلنر — پیشنهاددهنده هوشمند بک‌لینک و رپورتاژ (MVP)

ابتدا **وضعیت فعلی سایت مشتری** بررسی می‌شود (تحلیل خودکار + چند سؤال)، سپس کاربر بودجه، حوزه فعالیت،
کلمات کلیدی و ترجیحاتش را وارد می‌کند و سیستم از دیتابیس ناشران فارسی
سه سناریوی پلن لینک‌سازی (اقتصادی / متعادل / پرقدرت) می‌سازد: کدام سایت، چه محصولی، در کدام ماه،
با چه انکرتکستی، به کدام صفحه و با چه هزینه‌ای — به‌همراه دلیل انتخاب هر سایت و خروجی اکسل.

پلن کامل محصول: [docs/PLAN.md](docs/PLAN.md)

> این ریپو یک محصول دوم هم دارد: **سفرپلنر** (پیشنهاددهنده سفر) در پوشه [`travel_planner/`](travel_planner/README.md).

## اجرا

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload
# http://localhost:8000
```

تست‌ها: `pytest -q`

## ⚠️ داده‌های نمونه
فایل `data/publishers.csv` **ساختگی** است (دامنه‌های `.example`) و با
`python scripts/generate_sample_data.py > data/publishers.csv` ساخته شده است.
قبل از استفاده واقعی، داده‌ی ناشران واقعی را از تب «دیتابیس ناشران» (ورود CSV) یا با ویرایش همین فایل وارد کنید.

ستون‌های CSV:

| ستون | توضیح |
|---|---|
| `id` | شناسه یکتا |
| `name`, `domain` | نام و دامنه ناشر |
| `type` | `news_agency`, `news`, `niche`, `blog`, `directory` |
| `categories` | دسته‌ها با `\|` جدا شوند، مثلاً `technology\|business` (لیست در `app/catalog.py`) |
| `product` | `reportage`, `news_reportage`, `guest_post`, `backlink`, `directory_listing` |
| `price` | قیمت به تومان |
| `authority` | DA/DR بین ۰ تا ۱۰۰ |
| `monthly_traffic` | ترافیک ماهانه تخمینی |
| `outbound_per_month` | تعداد رپورتاژ منتشرشده در ماه (تشخیص لینک‌فارم) |
| `index_rate` | نرخ ایندکس رپورتاژها بین ۰ تا ۱ |
| `link_type` | `dofollow`, `nofollow`, `sponsored` |
| `permanent` | `true` / `false` |

## تحلیل وضعیت سایت مشتری

**۱. تحلیل خودکار** (`app/site_audit.py`, `POST /api/site/analyze`):
در دسترس بودن، HTTPS، سرعت پاسخ، noindex، عنوان و توضیحات متا، robots.txt، sitemap، حجم محتوا،
سلامت و قابلیت ایندکس **صفحات هدف**، تاریخ ثبت دامنه (RDAP)، سابقه آنلاین (اولین آرشیو Wayback Machine)
و اعتبار دامنه از OpenPageRank (با تنظیم `OPENPAGERANK_API_KEY`). خروجی: چک‌لیست و «درصد آمادگی برای لینک‌سازی».
اگر منبعی در دسترس نباشد، آن فیلد خالی می‌ماند و کاربر دستی پر می‌کند.
درخواست به آدرس‌های داخلی/خصوصی (حتی از طریق ریدایرکت) مسدود است.

> RDAP برای دامنه‌های ‎.ir تاریخ ثبت نمی‌دهد (سابقه Wayback جایگزین می‌شود) و archive.org از داخل ایران
> فیلتر است؛ طبق پلن، سرویس تحلیل را روی سرور خارج اجرا کنید.

**۲. سؤال از مشتری** (`SiteProfile`): اعتبار دامنه، عمر دامنه، ترافیک ارگانیک، تعداد دامنه‌های ارجاع‌دهنده،
صفحات ایندکس‌شده، اعتبار رقبا، خرید لینک در ۶ ماه اخیر، وضعیت انکرتکست‌های فعلی، سابقه پنالتی، محلی/سراسری.

**۳. اثر روی پلن** (`app/site_profile.py`):

| وضعیت | تغییر در پلن |
|---|---|
| سایت نوپا (عمر < ۱ سال، DA < ۱۰ یا < ۱۵ دامنه ارجاع‌دهنده) | سقف لینک ماهانه نصف، سهم وبلاگ/تخصصی/دایرکتوری بیشتر و خبرگزاری کمتر، انکر عمدتاً برند، بدون انکر دقیق، چیدمان از لینک ضعیف به قوی |
| سایت معتبر (DA ≥ ۳۵، ۳۰۰+ دامنه ارجاع‌دهنده یا ۱۰۰ هزار+ ترافیک) | سقف لینک ×۱.۵، سهم خبرگزاری و سایت خبری بیشتر |
| بدون لینک در ۶ ماه اخیر / لینک‌سازی مستمر | شروع تدریجی و سقف ×۰.۷۵ / سقف ×۱.۲۵ |
| انکرتکست‌های فعلی پر از کلمه کلیدی | حذف انکر دقیق و رقیق‌سازی با برند و آدرس سایت |
| سابقه پنالتی یا افت شدید | اجبار به استراتژی محافظه‌کار |
| فاصله ۲۰+ واحدی اعتبار با رقبا | وزن بیشتر به اعتبار ناشر و هشدار کمپین بلندمدت |
| کسب‌وکار محلی | سهم دایرکتوری‌ها ×۲ و یادآوری Google Business Profile و نقشه‌های داخلی |
| صفحات ایندکس‌شده کم / DA بالا با ترافیک خیلی کم | هشدار |

## منطق موتور

1. **امتیاز کیفیت** (`app/scoring.py`): ترکیب وزن‌دار اعتبار، ترافیک (لگاریتمی)، ارتباط موضوعی و نرخ ایندکس —
   وزن‌ها بر اساس هدف کاربر — منهای جریمه‌ی ریسک اسپم (اعتبار بالا با ترافیک کم، حجم بالای رپورتاژ، ایندکس ضعیف).
   لینک نوفالو/sponsored/موقت امتیاز کمتری می‌گیرد.
2. **فیلتر**: ارتباط موضوعی و سقف ریسک اسپم بسته به ریسک‌پذیری، و فیلترهای کاربر.
3. **بهینه‌سازی** (`app/optimizer.py`): کوله‌پشتی گروهی (حداکثر یک خرید از هر دامنه) که مجموع «قدرت لینک»
   را زیر سقف بودجه بیشینه می‌کند؛ بودجه ابتدا بین انواع سایت طبق ترکیب سناریو تقسیم می‌شود.
4. **سرعت لینک‌سازی طبیعی**: سقف لینک ماهانه (۴/۸/۱۵) با جستجوی دودویی روی «هزینه هر لینک» اعمال می‌شود
   تا بودجه به لینک‌های کمتر و قوی‌تر برسد، نه این‌که خرج نشود.
5. **انکرتکست و زمان‌بندی** (`app/anchors.py`, `app/planner.py`): توزیع برند/آدرس/عمومی/ترکیبی/دقیق،
   لینک‌های برند به صفحه اصلی، توزیع یکنواخت لینک‌های قوی بین ماه‌ها (تقویم شمسی) و پیشنهاد موضوع محتوا.

## API
- `POST /api/site/analyze` — تحلیل خودکار سایت و صفحات هدف
- `POST /api/plan` — ساخت پلن؛ فیلد `profile` وضعیت سایت را می‌گیرد (مستندات کامل: `/docs`)
- `GET /api/publishers`, `GET /api/publishers.csv`, `POST /api/publishers/import` (بدنه: متن CSV)
- `GET /api/meta` — برچسب‌ها و لیست‌ها
